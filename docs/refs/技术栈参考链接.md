## 二、面试高频追问 8 条

**① 已经有 BM25 了，为什么还要向量？**
BM25 是词面匹配，`OOMKilled`、`exit code 137` 这类精确 token 它无可替代；但它匹配不到"Pod 一直重启"↔"CrashLoopBackOff"这种同义改写。本项目实测：分源过滤路径 recall@20 = **1.000（12/12）**，关掉过滤回落到 **0.917（11/12）**，唯一漏掉的是 `Redis connection refused`——不过滤时 Top-20 里一条 redis 文档都没有（README §5.2）。这说明单路都会漏，双路才是下限保障（见表中第 11、15 项）。

**② RRF 为什么用倒数排名，而不是两路分数加权？**
余弦相似度被归一化到 0-1，BM25 分数无上界且随语料长度分布漂移，两者**量纲不可比**，加权求和前必须先归一化，而归一化系数要随语料重调。RRF 的 `Σ 1/(k+rank)` 只看名次，k=60 把头部差距压平，所以一路噪声大也压不垮整体——这正是 Cormack 2009 的结论（表中第 14 项）。代价也认：两路都弱时它区分不出强弱，极端情况只能靠重排兜底。

**③ 为什么不用本地 embedding / rerank？**
本机 Python 3.14 的 wheel 生态是风险点，且要下 95 MB embedder + 1.1 GB reranker 和 onnxruntime；全 API 化后环境从 10 分钟降到 2 分钟，换模型只改 `.env` 一个字符串（设计清单 §3.1）。代价是网络往返：实测 embedding 303 ms、rerank 200 ms，所以必须做 `sha256(model+text)` 的 embedding 落盘缓存——全量重建 98 s 后，二次运行是 **0 次 API / 0.2 s**。

**④ Cross-Encoder 为什么慢但准？**
bi-encoder 先把 query 和 doc 各自编码成向量，doc 向量可离线预计算，线上只做一次点积，复杂度与候选数无关但是"见过面"的近似匹配；cross-encoder 把两者拼接后过完整注意力，逐 token 交互，**没有可预计算的产物**，每个 (query, doc) 对都要一次前向，成本随候选数线性涨。所以工程上的标准做法就是两段式：向量/BM25 先粗排 Top20，cross-encoder 只精排这 20 条（表中第 17 项）。本项目实测 3 条候选 200 ms，按线性外推 20 条约 1 s 量级（这条是推算，没实测），这是它能进主链路的唯一理由。

**⑤ 引用校验怎么防幻觉？**
prompt 里要求"每条结论标 `[chunk_id]`"只是第一道，模型仍然会编 chunk_id；真正的闸门是生成后校验：**每个引用 id 必须出现在本次请求的上下文里**，不在就丢弃并重生成一次，再失败降级成原文片段（`degraded=true`）。这套"引用召回"的度量口径来自 ALCE（表中第 21 项）：评测时看的是"引用是否真的支持这句话"，不是"有没有链接"。代价明确：校验不过要多花一次 LLM 调用。

**⑥ 拒答阈值 0.35 怎么定的？**
先承认它是**初值，不是标定值**：bge-reranker-v2-m3 返回的就是归一化分数（实测相关片段 0.5587、无关片段 0.0000，中间几乎是空的），所以 0.35 落在间隔里先跑通链路。正式标定要在 D7 的 40 正 + 10 负评测集上画 ROC，按"误拒率可接受"反推阈值，并且**拒答率和误拒率必须同时报**（表中第 22 项的 risk–coverage 就是这件事）。只说"阈值 0.35"不说误拒率，是面试里最容易被戳穿的一句。

**⑦ 为什么不用 LangChain / LlamaIndex？**
它们解决的是"编排 + 集成 + 默认提示词"，代价是链路上每一层的默认值都看不到：切分参数、prompt 模板、重试策略都藏在封装里。本项目只有 5 个环节、每层都要报指标（recall@20、重排分、TTFT、成本），自写约 400 行更可控，也让"为什么 k=60""为什么 800 token"讲得出来。代价照实说：重试、缓存、评测脚本都得自己维护，这就是 tenacity、embed_cache、run_eval 存在的原因。

**⑧ 首 token ≤1.2 s 怎么做到，口径是什么？**
口径是**请求到 SSE 第一个 `delta` 帧**的时间，不含客户端渲染，也不是整卡时间（设计清单 §6.2）。做法是把帧序固定成 `meta`（Query 理解结果）→ `citations`（已确定的 chunk）→ `delta` → `done`：检索与重排一结束就能开流，首字不必等 LLM；拒答路径更早，不进 LLM 就返回完整卡片（<1 s）。但必须如实补一句：**这条门槛在 D5 之前是设计口径、没有实测**；已经实测的是检索热路径 P50 14 ms / P95 17 ms、embedding 303 ms、rerank 200 ms，而生成 400 token 要 2.7-3.3 s（约 130 token/s），所以整卡 3-4 s、P95 落在 4.5 s 量级，不承诺 2 s。
